# CI Library

Contains implementations and information on CI standards. This repository is not intended to be just a reference library, the implementations from here can and should be used in practice. For more best practices reference, see [markdown-pvarki-best_practices](https://github.com/pvarki/markdown-pvarki-best_practises).

## Development

Instructions for development in this repository.

### Pre-Commit

Pre-commit is configured under `.pre-commit-config.yaml`. The recommended tool to run it locally is [Prek](https://github.com/j178/prek), which is also used in the GitHub Action. There are no additional required dependencies apart from prek. Installing the pre-commit is done via `prek install`.

And checks can be manually run with `prek run --all-files`

#### Config Generation

Pre-commit configs for consuming repos are assembled from components under `pre-commit/configs/components/`. The combined configs are autogenerated — do not edit them directly.

Generation happens automatically on commit via the pre-commit hook. To regenerate manually:

```bash
bash pre-commit/configs/generate.sh generate \
  pre-commit/configs/python.pre-commit-config.yaml \
  pre-commit/configs/components/common.pre-commit-config-component.yaml \
  pre-commit/configs/components/python.pre-commit-config-component.yaml
```

Generated files have a clearly marked autogenerated section. Consuming repos can add their own hooks below the `>>> END AUTOGENERATED SECTION` delimiter without them being overwritten on updates (auto-updates are a TODO as of 2026-04-22).

### Versioning

This repo uses [bump-my-version](https://callowayproject.github.io/bump-my-version/), with the format `MAJOR.MINOR.PATCH-YYMMDD`. Version can be incremented using the [CLI tool for bump-my-version](https://callowayproject.github.io/bump-my-version/tutorials/getting-started/#installation):

```bash
bump-my-version bump <patch|minor|major>
```

You can also check the effect on the version using the following command (note that the date is automatically incremented appropriately):

```bash
bump-my-version show-bump
0.1.0-260420 ── bump ─┬─ major ─── 1.0.0-260421
                      ├─ minor ─── 0.2.0-260421
                      ├─ patch ─── 0.1.1-260421
                      ╰─ release ─ 0.1.0-260421
```

## Usage in other repositories

### Reusable workflows

A general reusable workflow is available that runs prek pre-commit checks and bumpversion validation:

```yaml
jobs:
  checks:
    uses: pvarki/config-ci-library/.github/workflows/general-check.yml@main
```

Both checks are enabled by default. To disable either:

```yaml
jobs:
  checks:
    uses: pvarki/config-ci-library/.github/workflows/general-check.yml@main
    with:
      run-bumpversion: false
      run-prek: false
```

### Composite actions

Individual actions can also be used directly:

```yaml
- uses: pvarki/config-ci-library/.github/actions/validate-bumpversion@main
```

### Pre-commit configs

Copy the relevant generated config from `pre-commit/configs/` into your repo as `.pre-commit-config.yaml`. Repo-specific hooks can be added below the `END AUTOGENERATED SECTION` comment. To stay up to date, replace everything between the `BEGIN` and `END` delimiters when a new version is released. This is a manual process for now.
