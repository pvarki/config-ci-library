# Pre-commit configs

Pre-commits are assembled from components, under `/components`. Main config files can be compiled
from multiple components:

| Config                                     | common-base | common-format | python | typescript | golang | kubernetes | terraform |
| ------------------------------------------ | :---------: | :-----------: | :----: | :--------: | :----: | :--------: | :-------: |
| `python.pre-commit-config.yaml`            |      ✓      |       ✓       |   ✓    |            |        |            |           |
| `typescript.pre-commit-config.yaml`        |      ✓      |       ✓       |        |     ✓      |        |            |           |
| `python+typescript.pre-commit-config.yaml` |      ✓      |       ✓       |   ✓    |     ✓      |        |            |           |
| `golang.pre-commit-config.yaml`            |      ✓      |       ✓       |        |            |   ✓    |            |           |
| `kubernetes.pre-commit-config.yaml`        |      ✓      |               |        |            |        |     ✓      |           |
| `terraform.pre-commit-config.yaml`         |      ✓      |       ✓       |        |            |        |            |     ✓     |

(Columns are the components under `/components`; rows are the generated configs.)

`common-base` holds universal hooks; `common-format` holds prettier and can be omitted for languages that bring their own formatter (e.g. the `kubernetes` config uses yamlfmt instead).

## Required tooling

Most hooks bring their own dependencies, but some expect binaries on `PATH`:

| Component | Required on `PATH`             |
| --------- | ------------------------------ |
| python    | `mypy` (from the project venv) |
| golang    | `go`                           |
| terraform | nothing                        |

`terraform`, `tflint` and `trivy` are pinned via `--hook-config=--tool-version=` and downloaded into
`~/.cache/pre-commit-terraform` (or `$PCT_TOOL_CACHE_DIR`) on first run, so none of them need to be
installed and every developer and CI run uses the same version. Nothing is installed system-wide and
whatever is on `PATH` is ignored — set `--hook-config=--tool-version-mode=prefer-local` to use a local
binary instead.

A repo whose `required_version` conflicts with the pinned Terraform must widen its constraint (an exact
`required_version = "1.5.7"` fails against any other version, including in CI) or override
`--tool-version` below the autogenerated section.

`terraform_validate` runs `terraform init -backend=false` when needed, so it requires no cloud
credentials or backend access, but it does download providers. `terraform_tflint` runs `tflint --init`
itself, so plugins declared in `.tflint.hcl` are installed automatically.

`terraform_validate`'s `--hook-config=--retry-once-with-cleanup=true` is deliberately not set: it is
the only hook option in this component that needs a tool we cannot pin (`jq`, to parse
`terraform validate -json`). It only adds a second recovery attempt that wipes `.terraform/{modules,providers}`
before re-initialising; without it a stale cache is fixed by deleting `.terraform` by hand. A repo that
wants it can add it below the autogenerated section and install `jq`.

To use OpenTofu instead of Terraform, change `--tf-path=terraform` to `--tf-path=opentofu` and set a
matching `--tool-version` in the component. `--tf-path` is set explicitly so the choice does not depend
on which binary happens to be on `PATH`.

The generate.sh script is used to autogenerate the files. This runs during pre-commit, and automatically adds generated files to the commit.

## Variable substitution

Components can reference `${KEY}` placeholders that `generate.sh` substitutes at generation time. Pass values as trailing args after `--`:

```bash
bash pre-commit/configs/generate.sh generate <output> <component>... -- KEY=value
```

The TypeScript component uses `${TS_DIR}` to control where `pnpm` runs. The standalone config (`typescript.pre-commit-config.yaml`) sets `TS_DIR=.`; the combined config (`python+typescript.pre-commit-config.yaml`) sets `TS_DIR=ui` to match the convention of nesting the frontend in `ui/`.
